# 元件製作與重複使用流程 v0.1

## 1. 視覺基準

- 原創 Q 版生活模擬風格：角色約 1.5–2 頭身，人物視覺優先，建築和物件簡化。
- 莫蘭迪低彩度色票：暖米白 `#E8E1D7`、沙岩米 `#C8B9A8`、鼠尾草綠 `#9AA58F`、灰霧藍 `#8296A1`、灰粉玫瑰 `#B98F91`、灰藍炭 `#55656B`。
- 霧面材質、寬大形體、柔和陰影；每個資產最多 3 種主要材質。避免高飽和、細碎紋理、複雜透明與過度精緻的小配件。
- 參考「乳癌希望之島_莫蘭迪低模全景_v4」與「乳癌希望之島_六角照護群島_v5」的構圖概念；重做為本案原創造型，不複製第三方遊戲角色、程式或素材。

## 2. 每個元件都走同一條流程

| 階段 | 工作 | 必備輸出 | 放行條件 |
|---|---|---|---|
| 0. 建立需求 | 指定用途、所在島區、互動、尺寸、內容責任人 | 完整 `component.yaml` brief | ID、用途、尺度、互動已填 |
| 1. 定義造型 | 固定輪廓、視角、顏色、材質與簡化程度 | 參考圖／turnaround | 角色至少正、側、背、斜角；建築至少正、側、背、俯視 |
| 2. 灰模 | Blender 基本體塊搭建，按規定原點與比例 | `source/model.blend` 灰模截圖 | 遠看剪影可辨識；尺寸與碰撞範圍正確 |
| 3. 低模與材質 | 控制面數、合併材質、設 LOD；角色加共用骨架 | 可動畫模型與 LOD | 配色符合色票；沒有不可見細節浪費面數 |
| 4. 封裝匯出 | 匯出 glTF 2.0 / GLB、metadata、預覽圖 | `export/*.glb`、`preview.png` | 名稱、方向、尺寸、貼圖與版本一致 |
| 5. 場景整合 | 放入隔離測試島，綁定互動 ID 與碰撞體 | 網頁場景預覽 | 角色不穿地／建築；據點可點；手機可辨識 |
| 6. 驗收與發布 | 視覺、效能、內容責任人檢查，記錄批准版本 | 狀態改為 `approved` | 清單全通過，版本可追溯與回退 |

概念圖未確認前不進入細模；GLB 未通過場景預覽前不進入正式網站。模型檔與衛教文字分開管理，避免改文案時重匯模型。

全島與單島不得建立兩套外觀不同的模型。每座島只維護一個正式 GLB；全島鳥瞰與單島近景只切換相機及同一 GLB 內的 LOD。每座島須保存一張 16:9 電影基準圖及一張固定相機的 WebGL 驗收截圖，並排比對島形、建築、道路、岩岸、植栽、材質和接口；不一致時回到 Blender 重建後重新截圖。

## 3. 元件類型專用視圖

- 角色 `CHR`：正面、左／右側面、背面、左右斜前；中性 A-pose。第一版角色共用比例、骨架與動畫命名。
- 建築 `BLD`：正面、左右側、背面、俯視與 3/4 角；另標入口方向、互動點、人物尺度參照。
- 地形／六角區 `ENV`：俯視佈局、四邊高度、相鄰拼接狀態、俯視與 3/4 視角；需標準邊界尺寸。
- 道具 `PROP`：正面、側面、背面、俯視；定義擺放錨點與碰撞盒，可重複排列。
- 介面／圖示 `UI`：明暗底、選取／預設／停用等狀態，使用 SVG 或 CSS 優先；不要把文字烘焙進 3D 貼圖。

## 4. 檔名與資料夾

每個資產使用穩定 ID：`<類型>-<用途>-<三位序號>`，例如 `CHR-VISITOR-001`、`BLD-MAMMO-001`、`ENV-HEX-CARE-001`、`PROP-BENCH-001`、`UI-PLACE-CARD-001`。

```text
assets/<ID>/
  component.yaml
  reference/turnaround-v01.png
  source/model.blend
  export/<id-lowercase>.glb
  export/preview.png
```

設計變更升版：`v0.x` 為概念或未核准，`v1.0.0` 為首個核准版；修改以相容為主升 patch，外觀或骨架變更升 minor，破壞既有場景連結或動畫契約升 major。使用 `component.yaml` 中的穩定 `id` 綁定程式，不用檔名或顯示名稱當資料鍵。

## 5. 共用技術規則

- 單位採 Blender 米制；資產底部中心作原點，角色面向 Blender `+Y`、`+Z` 向上。GLB 由匯出器完成座標轉換，匯入後需檢查朝向。
- 角色基準高度正規化為 1.0；建築尺寸記錄為角色高度倍數，方便保持「人物大、房屋小」的比例。
- 角色動畫名稱固定 `idle`、`walk`、`interact`、`wave`；場景控制程式以名稱呼叫動畫，不依賴 Blender action 順序。
- 原型資產優先不帶貼圖；若需貼圖，採共用圖集，避免每個元件多張高解析貼圖。
- 動態角色模型預算：基礎 LOD0 約 6,000 三角形，LOD1 約 2,500，遠景 LOD2 約 800；依目標設備實測調整。
- 單島區場景需註明總三角形、材質數、貼圖大小、GLB 檔案大小、draw calls。不要只記模型面數。

## 6. 發布檢核清單

- [ ] 造型與莫蘭迪低彩度樣式一致，沒有不必要的細節。
- [ ] 概念視圖可支援建模；主要角度比例、服裝、色彩一致。
- [ ] 元件 ID、版本、原點、面向、尺寸、碰撞體和互動 ID 已填。
- [ ] GLB 可匯入 Three.js；無遺失材質、貼圖或錯誤旋轉。
- [ ] LOD 切換不跳位；角色動畫名稱可由網頁端找到。
- [ ] 手機視角和 4K 鳥瞰畫面都可辨識，且不遮住衛教文字。
- [ ] 內容責任人與必要審閱者完成確認；醫療資訊不直接烘焙在模型上。
- [ ] `.blend`、turnaround、GLB、metadata 均與本次版本一起封存。

## 7. 角色共用骨架與服裝變體

先建立一套身體比例與骨架，再以頭髮、臉部、服裝和配件建立變體：病友／訪客日常服、醫師白袍、護理師制服、手術室刷手服。男女外觀呈現不更換角色 ID；使用 `gender_presentation` 與 `outfit_variant` 兩個欄位組合，避免重複建模。服裝差異較大的手術帽、口罩、白袍可獨立 mesh/material，仍沿用同一骨架和動畫契約。

角色矩陣圖只作為造型方向。每個被選定的服裝變體進入 Blender 前，需補一張同風格多角度圖並由視覺負責人確認；手術帽、口罩、刷手服等臨床服裝由院內使用者確認。

## 8. 上傳照片建立角色的資料流程

目前原型只在瀏覽器本機將照片裁切到頭像預覽，不會上傳或保存，也不是真正的 3D 臉部建模。正式 3D 版本優先採本機臉部貼圖、明確同意、可跳過與隨時刪除；若要雲端生成，須先完成院方個資／資安審查，且不可在未同意下把照片放上大螢幕或送入活動統計。

## 9. 建築與科室模組

- 主建築 `BLD-NTUCC-001` 依院方空拍與外觀照片保留中央弧形深色玻璃塔、低樓翼樓與入口雨棚，簡化屋頂、窗格和周邊細節。正式建模前請院方確認量體與素材授權範圍。
- 科室小屋採 `BLD-DEPARTMENT-001` 共用母型；門、窗、屋頂、坡道和招牌底板可重用。科室差異用可替換圖示及網頁文字完成，避免每一科重新建築，也避免把文字烘焙在貼圖內。
- 第一批科室變體：`BLD-MAMMO-001`、`BLD-ULTRASOUND-001`、`BLD-PATHOLOGY-001`、`BLD-CHEMO-001`、`BLD-OR-001`、`BLD-RADIOTHERAPY-001`。正式名稱、路徑和內容需由院內單位確認。
