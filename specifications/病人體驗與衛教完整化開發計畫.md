# 病人體驗與衛教完整化開發計畫

更新：2026-11-05。狀態：開發規劃；下列待辦不代表已完成。本文與使用者最新決議優先於早期寫實海報、橋梁與大量人流的規格。

## 工作目標

讓病人能在同一座臺灣輪廓的十島世界中行走，找到適合自己的衛教、整理想問醫療團隊的問題，並留下願望。少量精緻島民透過可觀察的日常作息，讓島嶼有生活感。電影劇照應呈現這個可實際探索的世界。

成功不以模型數、問答答對率或全島打卡率判定，而是病人是否能找到資訊、理解重點、保存問題並完成想做的互動。

## 一、模型與電影使用同一個世界

保留已確認的簡單可愛人物與柔和島嶼風格；醫院保有可辨識的真實外觀。十島不做規則六角形，不新增架高橋梁，維持不規則拼圖與近岸連通。

模型分為人物、建築、植栽、岸石、海面及天空元件，各自保存來源、版本與碰撞體。電影可以提高光影、抗鋸齒、材質解析度與景深，但不得另畫不同的地形、建築比例或角色。以同一套模型輸出劇照，避免反覆追逐無法落地的生成海報。

先鎖定四個驗收鏡位：白天全景、醫院入口、夜間許願、流星抵達燈塔。每個鏡位保存相機位置、目標、視角、日夜狀態與資產版本，並排比較網頁截圖與電影輸出。先驗收輪廓、構圖、地標與動線，再精修近景材質、植栽層次及人物表情。

WebGL 不直接承載電影用的最高面數模型。使用同造型的遠近細節版本、共用材質與實例化裝飾；遠景降細節，近景保留臉部、衣著與醫院立面。電影可使用高解析版本，但主要輪廓一致。記錄下載大小、記憶體、繪製次數與畫格時間；以選定桌機穩定 50–60 fps、目標手機 30 fps 為待驗證目標，不視為目前保證。DGX Spark 不列為網站執行依賴；需要生成時另作有限量工作，依監測溫度降載。

## 二、病人的核心體驗

首條完整體驗：**醫院迎賓 → 步行至病理島 → 接近衛教站 → 閱讀重點 → 收藏想問的問題 → 前往燈塔許願 → 日後回來完成願望。**

1. 首頁可選「我想了解什麼」，不要求輸入病歷或先判定疾病階段。建議路線只是導覽，不代表個人治療順序。
2. 同一場景內提供鍵盤／觸控移動、目的地標示與路徑提示。抵達據點後，以按鈕或 E 開啟內容；角色與導覽不擋門口。
3. 每單元先提供約 20 秒可讀摘要，再展開 2–3 分鐘內容、圖解與常見問題；提供字級調整、鍵盤操作、圖片替代文字，影片須有字幕。
4. 可選擇一題理解確認並顯示解釋；答錯不懲罰、不封鎖內容。病人可略過問答直接收藏。
5. 保存「今天看過的重點」與「下次想問醫師的問題」，可回看及清除。學習進度與願望完成各自獨立，不暗示疾病改善。
6. 另提供文字版衛教目錄與搜尋；不想走路、WebGL 不可用或操作不便時，仍能取得同樣完整內容。島民休息不會造成衛教關閉。

## 三、十島內容矩陣

第一批目標為每島 4 個短單元，共 40 個；這是待編撰清單，不是現有內容量。各單元再含摘要、常見問題、與醫療團隊討論的問題及可追溯來源。

| 島嶼 | 第一批四個單元主題 |
|---|---|
| 病理科／微觀花園 | 報告與團隊角色；常見報告名詞；報告出來後的討論；我的提問清單 |
| 影像醫學／光影觀察所 | 為何安排檢查；不同檢查的用途；檢查前準備；結果如何與團隊討論 |
| 腫瘤內科／陪伴庭院 | 治療類別概覽；門診前準備；治療期間的紀錄；不適時如何聯絡團隊 |
| 腫瘤外科／綠蔭照護站 | 手術選項討論；術前準備；住院與返家流程；回診問題整理 |
| 整形外科／重建花園 | 是否重建的選擇；重建方式與時機的討論；期待與恢復；身體感受與支持 |
| 放射腫瘤科／星光庭院 | 治療目的；定位與療程流程；期間照護；回診與常見問題 |
| 心臟科／心律水庭 | 為何安排評估；檢查與追蹤；症狀紀錄；跨科與用藥溝通 |
| 家庭醫學科／日常小屋 | 日常健康管理；用藥清單；睡眠與生活支持；長期照護與資源 |
| 復健科／活力步道 | 復健評估；活動與個別運動計畫；上肢與腫脹照護提問；回到日常生活 |
| 生育保存／種子溫室 | 何時提出需求；諮詢與轉介；可討論的選項；伴侶溝通與資源 |

情緒、營養、身體意象與親密關係、家屬照護、工作及經濟資源作為跨島主題標籤，避免全部塞進單一科別。緊急處置、藥物、運動及治療建議必須有適用條件與院方審閱，不能由遊戲角色臨場生成處方。

內容資料欄位：`id / islandId / anchorId / title / objective / summary / sections / questions / sources / version / status / reviewedBy / reviewedAt / reviewDue / accessibility`。狀態為草稿、待審、已核准、已撤下；正式站只公開已核准版本。內容改版保留既有收藏與對應版本，過期內容提示重新審閱，不悄悄視為最新。

候選資料來源（編撰前逐單元核對日期與適用性）：[臺大乳房醫學中心](https://www.ntuh.gov.tw/BC/Index.action?l=zh_TW)、[臺大醫院乳癌藥物治療衛教影片](https://media.ntuh.gov.tw/media/1105)、[臺大乳房重建常見問答](https://www.ntuh.gov.tw/BC/Faq.action?agroup=a&fid=583&q_type=-1)、[NCI 治療後生活與照護](https://www.cancer.gov/types/breast/breast-cancer-survivorship)。引用來源不等同本專案已通過院方審核。

## 四、完整許願、點燈與流星

完整版本以院內本機 API 與 SQLite 保存資料，瀏覽器快取只作斷線展示。願望使用隨機 ID 與獨立完成憑證，不收姓名或病歷號，公開畫面不顯示願望全文。

狀態：`created → lit → completed → archived`。送出成功後點亮所屬島嶼上空的星星，並取得個人 QR；之後掃描 QR 自動回報完成，不增加填表或第二次確認。QR 的 GET 只載入頁面，頁面再送出帶憑證的完成 POST，降低網址預覽誤觸風險；完成請求必須可重複呼叫而只產生一個事件。

院內主畫面訂閱事件，星星化為金色流星飛向燈塔，燈塔與沿途路燈回應，最後保留封存星光。個人完成頁依原規格只顯示「願望完成」及 QR。減少動態模式改為依序增亮。

伺服器保存事件 ID、順序及完成時間；展示端記錄已播放事件，重新連線取得狀態與游標，避免重新整理、重複掃描或重啟造成重複流星。完成狀態先保存，動畫失敗不回滾完成。多筆事件排隊播放，離線與失敗須明確回饋；未成功保存不可假裝已點亮。

驗收：兩個瀏覽器／手機與展示端建立及完成同一願望；重複掃描只完成一次；重新整理不重播；伺服器重啟不遺失；斷線後恢復狀態正確；減少動態有效。院內網址、手機網路可達性、保存期限及刪除流程須在現場部署前落實；localhost 不能當手機 QR 網址。

## 五、島民作息與實際事件日誌

預設 8 位背景島民，保留 6／8／12 位選項；玩家另計。以移動、看診準備、休息、閱讀與聊天輪替呈現生活感，局部互動點同時 2–3 位，保留視覺留白與寬通道。

每位島民有角色、活動表、目的地、開始時間、停留時間及可用互動點。示例時間是遊戲模擬時間，不是院方門診表，也不將所有檢查與治療塞入同一病人的一天。

| 模擬時間 | 島民 | 預定活動 |
|---|---|---|
| 08:30 | 護理師 A | 前往醫院迎賓區準備 |
| 08:35 | 醫師 B | 步行至病理島諮詢點 |
| 08:40 | 島民 C | 在病理花園閱讀報告名詞 |
| 08:50 | 島民 C | 前往庭院休息、整理問題 |
| 09:00 | 島民 D | 前往影像島認識檢查流程 |
| 09:15 | 島民 E | 在燈塔廣場留下模擬願望 |

活動狀態：等待開始 → 前往 → 抵達 → 互動／工作／休息 → 結束。日誌只在真正狀態轉換時產生：「08:36 醫師 B 抵達微觀花園」必須由位置到達判定觸發，不以排程時間假裝到達。保留預定與實際時間；遇到堵塞重新找路，逾時記錄延後，不穿牆、不瞬間傳送。

事件欄位：`eventId / residentId / scenarioId / simAt / plannedAt / eventType / from / to / activityId / contentId / result`。環形緩衝保留最近事件，日誌可暫停捲動、依島／人物篩選、點擊追蹤同一場景內的角色。模擬資料明確標記，不混入病人個人的閱讀或願望紀錄。

預設 1 真實分鐘對應 15 模擬分鐘，供展示調整；病人的閱讀時間不加速。場景暫停後恢復須有明確時鐘策略，避免瞬間補播大量事件。「島嶼概況」由實際角色位置與活動狀態統計人數及活動，不顯示虛構的真實門診量。

## 六、交付順序與驗收門檻

| 階段 | 可實際體驗的交付物 | 完成條件 |
|---|---|---|
| 1：病理島完整範例 | 迎賓導覽、可走到的衛教站、4 單元架構、收藏與問題清單 | 可從地圖步行開啟內容；關閉後繼續走；刷新保存；文字目錄同樣可用；草稿不可冒充核准內容 |
| 2：星願完整服務 | 院內 API、資料庫、個人 QR、展示端同步、封存 | 通過前述跨裝置、重複完成、重啟與斷線驗收；實際完成頁符合原規格 |
| 3：生活作息 | 8 位島民活動表、實際事件日誌、島嶼概況 | 觀察一整個模擬日；日誌時間與實際抵達吻合；堵塞可恢復；不累積重複事件 |
| 4：十島衛教 | 40 個短單元及跨島標籤、搜尋、相關內容推薦 | 逐單元具來源、版本與審閱紀錄；每島可步行抵達；不要求病人完成全部島嶼 |
| 5：美術與效能收斂 | 逐元件精修、四張同資產劇照、手機操作調整 | 相同鏡位逐項對照；桌機與選定手機實測；無障礙文字入口仍可完成核心任務 |

美術可以持續細化，但不阻塞階段 1 的可用體驗。下一個明確施工項目是「病理島衛教站＋可保存的提問清單」，不是再新增一批無互動的裝飾。以首次使用者測試是否能自行找到據點、理解如何返回地圖與找回收藏，再決定擴充速度。
