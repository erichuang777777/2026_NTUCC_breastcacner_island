# 希望島 v20：院區辨識、內容管理與角色互動

日期：2026-11-11
狀態：開發提案；本文件不表示下列功能已實作。

## 現況依據

- `webgl-prototype/hope-avatar.js` 與角色 v04 manifest：六種真正的骨架 3D 角色，模型約 2.2–2.5 萬面，已有 idle、walk、wave、read；質感提升應從造型、材質、蒙皮、表情著手。
- `hope-education.js`：十站各三個示範單元，資料直接定義於程式；三題理解闖關另行定義。
- `hope-server.py`：共用 SQLite 已有角色與願望等資料表，目前沒有文章、附件、版本與發布管理 API。
- `hope-landscapes.js`：十科已有不同量體與道具；全景的建築尺寸與相近材質削弱辨識。
- `taiwan-study.js`：目前載入 `ntucc-blender-v06.glb` 作為醫院模型，有醫院特寫鏡頭；預設全景仍以臺灣輪廓為中心。

## 1. 人物品質

延續早期定稿的親切、可愛比例，往動畫電影的材質與動作品質提升。先完成一位病友與一位醫護的品質樣本，再擴展六種角色。

製作範圍：臉部輪廓、眼皮、眼球與高光、耳鼻嘴體積；髮束與頭巾摺痕；衣領、袖口、縫線、鞋底；皮膚、布料、鞋與頭髮分開調整材質。高精度雕塑細節烘焙至網頁模型的法線與粗糙度貼圖。修正肩肘、膝蓋與手腕的彎曲變形，補上眼神與細微表情。

同一骨架、同一套動畫與外觀設定沿用於玩家及居民。近景、中景、遠景採用適合的細節層級。驗收包含正側背與轉身近拍、走路、坐下、揮手、持物，以及 8／12 人實機效能；初步目標為指定展示設備上穩定 30 FPS，尚需量測確認。

參考技術：https://docs.blender.org/manual/en/5.0/addons/import_export/scene_gltf2.html

## 2. 衛教內容管理

新增獨立 `/education-admin.html`；投影頁提供另開管理頁的入口，維持投影不中斷。

首版功能：文章清單、搜尋、科別與照護階段篩選；新增與修改標題、摘要、內文、封面、排序；PDF、DOCX、JPG、PNG 附件上傳與替換；草稿、待審閱、發布、下架；來源、作者／審閱者與更新日期；版本紀錄與還原。

PDF 提供預覽；DOCX 首版提供附件與下載，不將「上傳 Word」誤標為已完成可靠的全文轉換。文章內文可獨立編輯，附件保留原始檔。日後文字擷取須先產生草稿供確認。

沿用 SQLite，新增 articles、article_revisions、attachments 與 article_stations 關聯；文章可對應多科。同一篇文章與三題測驗分開管理，文章發布不直接改動測驗答案。

管理者登入後才能修改；患者端僅讀取已發布版本。上傳採允許格式、大小限制、實際格式檢查、伺服器產生儲存名稱與安全下載路由。文章內文須安全呈現，附件與文章備份必須一起處理。草稿編輯與發布版本分開，避免修改草稿立即改掉公開內容。

驗收流程：新增文章 → 上傳 PDF → 指定影像醫學站 → 預覽 → 發布 → 從站點讀到新內容 → 修改草稿不影響線上版本 → 再發布 → 下架／還原。包含重新啟動伺服器後持續存在，以及未登入者無法寫入。

## 3. 臺大癌醫建築群

建立院區資產盤點，逐棟對應官方資料、現場外觀照片、既有模型與可確認的相對位置。先補完整主體的側翼、低層量體、入口雨棚、前庭與植栽，再依確定的資料建立其他院區建築。不要把醫療功能名稱直接假設成獨立建物，也不要宣稱未核對建物的真實位置或外觀已完全還原。

遊戲中的科別建築明確定位為主題化照護站；寫實院區建築另外依真實參考建模。設計中的海上希望燈塔與院內實際設施也應在介紹中清楚辨識。

官方樓層資料：https://www.ntucc.gov.tw/ntucc/group-page/floor-guide?muid=184&tabsIndex=1

## 4. 十科建築辨識

共用院區品牌材質與導覽系統，各科以量體、入口、屋頂、庭院活動及符號形成差異；差異不能只靠顏色。

| 科別 | 提案特徵 |
| --- | --- |
| 病理科 | 層疊玻璃研究館、切片形遮棚、顯微展示窗 |
| 影像醫學 | 環形入口、放射狀採光構件、檢查導覽區 |
| 腫瘤內科 | 開放陪伴庭院、舒適座椅與植栽廊架 |
| 腫瘤外科 | 清楚的現代量體、寬入口、術前說明亭 |
| 整形外科 | 曲面立面、弧形連廊與重建花園 |
| 放射腫瘤科 | 弧形遮棚、精準光線主題、療程說明空間 |
| 心臟科 | 心律立面符號、水庭、休息與量測空間 |
| 家庭醫學科 | 家屋尺度、門廊、日常照護小庭院 |
| 復健科 | 開放運動棚、無障礙坡道、活動平台 |
| 生育保存 | 種子溫室、嫩芽結構、安靜諮詢花園 |

先製作影像醫學、復健、生育保存三種差異大的樣本，於實際全景與近景檢查。收斂標準是縮小後仍有不同輪廓、入口清楚、標示可讀，且不遮擋醫院主體或原有通道。

## 5. 角色互動與日常生活

第一批：相遇轉頭與招手、兩人短暫交談、坐下與起身、醫護指示導覽、居民點頭回應、翻閱手冊、許願時抬頭與揮手。

第二批：陪伴散步、復健活動、照顧花圃、雙人看海、引導新居民。

行為狀態涵蓋散步、前往活動點、預約位置、就位、活動、離場與中斷。雙人活動需同時預約兩個站位、先面向彼此；只在不阻擋通行的位置觸發。玩家接近可打招呼或開始衛教；活動超時、路線受阻或切換角色時，釋放位置並正常離場。延續 v19 的位置預約與避讓，避免互動重新造成入口壅塞。

日誌由實際狀態事件產生。背景居民的模擬閱讀紀錄與使用者本人閱讀、測驗通關分開，不將模擬事件誤算為使用者學習成果。

## 6. 地圖與視覺中心

保留同一個可連續探索的十島世界與臺灣外輪廓，重新配置內部院區占比與前庭留白。臺大癌醫建築群為主要視覺焦點，希望燈塔為次要焦點，各科主題站形成周圍探索節點。

預設鏡頭採醫院正面斜角，呈現主建築、院區名稱、希望燈塔與居民活動；臺灣全景保留為同一場景的鏡頭選項，不另外切換成不同世界。主畫面以「臺大癌醫・希望之島」作為辨識提案。透過建築群尺度、立面辨識、前庭留白與夜間照明凸顯醫院，不只依靠文字標誌。

調整順序：先在既有地形試鏡頭與院區配置，再視實際遮擋與可用面積微調內部島塊。維持原定無橋樑、相接海岸的世界設計。任何變更後重跑 v19 尋路與 8／12 人模擬。

## 建議交付順序

1. 可用的衛教管理首版：完成一篇文章從管理頁到科別站點的完整發布流程。
2. 醫院主視角與院區配置樣本：同場景提供全景、醫院近景及夜景檢視。
3. 一位病友、一位醫護與一組雙人互動；同時完成三科建築辨識樣本。
4. 依樣本擴展角色、其餘七科建築與日常互動，整合效能及導航驗收。

以上是六項需求的具體提案與驗收標準，不代表新增院區外觀已經過官方資料完整核對，也不代表尚未製作的模型與後台已交付。
